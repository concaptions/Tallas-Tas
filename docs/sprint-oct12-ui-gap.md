## Method

Each board was read whole by two independent lenses — **V** (visual: colour, type, spacing, radii, shadows,
icons, chip styling) and **A** (anatomy: regions, states, interactions, data, behaviour vs decisions, copy) —
each producing a findings table with `B<board>.<lens><seq>` IDs. This document merges the twelve tables board
by board, keeps every extractor ID, folds duplicates under one canonical ID (the alias is named in the row),
rules on every disagreement (section "Conflicts between lenses"), and groups the open gaps into file-disjoint
work packages so implementers can run in parallel.

Three facts frame every table:

1. **The boards predate the Oct 12 consolidation** (Ticket 5, migration 0067, `docs/decisions.md` Phase A entry).
   The internal track is ONE list — `draft → sent_to_editor_or_designer → under_editing_or_designing →
   ad_submitted → revisions_needed → revisions_submitted → approved` (`packages/domain/src/state/creative-status.ts:30-68`);
   `launched` is client-only (`:99-102`); `on_hold` is gone (`:15-16`); `INTERNAL_ENTRY_STATUS = 'draft'` (`:115`).
   Every board key from the old per-track lists (`sent_to_video_editor`, `sent_to_designer`, `videos_revisions`,
   `images_revisions`, `video_editing_in_progress`, `static_design_in_progress`, internal `launched`, `on_hold`)
   and all three "spec bugs" in `index.html` are inverted by it. Those rows are **board-predates-consolidation;
   code is right** and carry no work. An implementer who "fixes" the code toward the board reintroduces keys
   0067 removed; `creative-status.test.ts:24-53` fails the suite if any comes back.
2. **Decision 3 overrides board 1's enabled Approve**: Approve IS the submission, so it is QA-gated; Submit to
   Client is the client-track resubmission (`revisions_needed → revisions_submitted`) and reads "This creative is
   already with the client." at `pending_for_approval`. Rows that follow from this are **by design, keep code**.
3. **The backend contract is frozen.** Every change below rides the existing Server Actions and domain rules; the
   four writer-side defects board 5 surfaced are listed as escalations, not as work in this ticket.

## Hard rules the implementation follows

- Never change the backend contract (Server Actions, domain rules, schema).
- Every colour through a semantic token class (`bg-surface`, `text-text2`, `border-line`, `bg-accent`, `text-ok`,
  `bg-ok/10`, …); a board colour that no token covers gets a token in `tokens.css` FIRST (section "Token gap").
  `no-hex.test.ts` scans `packages/ui/src` and `apps/web/src` for any hex outside `tokens.css`.
- Every chip tone through `ChipTone` / `chipTone(label)` from `@tas/domain/state`; every pill is `StatusChip`.
- Every icon from lucide-react (installed `1.46.0`, a dependency of `@tas/ui` only — see "Icon map" for the gateway).
- Every spacing and radius on the Tailwind scale / the two radius tokens (`rounded-input` 6px, `rounded-card` 8px;
  `rounded-sm` resolves to 4px through the shadcn alias `--radius-sm`, `tokens.css:176`). Never `rounded-full` on a button.
- Reuse `AirtableGrid`, `KanbanBoard`, the `Sheet` primitive and `SelectionBar`; every new or changed primitive and
  every status-bearing component gets a story on `/design-system`.

- **"Palette is `tokens.css` verbatim (dark `:root`)"** — TRUE on all six boards. Every board declares the same
